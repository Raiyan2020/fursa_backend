## إضافة 21 يونيو — حالات زر التسجيل

المطلوب: Register / UNRegister / Full / Closed / Started / Ended

**الحالة: ✅ نُفّذ في الباك إند.** أُضيف حقل `action_state` محسوب مركزيًا يرجّع إحدى القيم الست (`register` / `unregister` / `full` / `closed` / `started` / `ended`) في كل payload للفرص والفعاليات، مع `is_full` و`has_started` و`has_ended`. الفرونت يعرض الزر حسب القيمة بدون أي حساب محلي.

**البيانات الخام لا تزال متوفرة أيضًا:** الـ API يرجّع كل المكوّنات:
`opportunity_status` · `is_registration_open` · `is_registration_closed` · `is_registered` ·
`participants_needed` · `registered_volunteers_count`

ترتيب الأولوية في الباك إند: `ended` → `started` → `unregister` → `closed` → `full` → `register`.

## ما نُفّذ في هذه الجولة

1. رندر الشهادات HTML يدعم العربية + مسارات عرض وإصدار (يحل مشكلة الأسماء العربية).
2. إرسال إيميل فعلي لإشعارات الفرص الجديدة المطابقة للفئة العمرية.
3. تسمية «التطور / Development» في كل ترجمات لوحة التحكم.
4. حذف الكلندر ونوع الفكرة «تحتاج دعم» من الباك إند.
5. `POST /api/events/{id}/close-registration/` + أزرار إغلاق/إعادة فتح في لوحة التحكم.
6. بانر مستقل لكل صفحة عبر `placement` (رئيسية / فرص / تطور / فعاليات).
7. حقل `action_state` الموحّد لحالات زر التسجيل الست.
8. تاقات `relationship_tags` (منظم / راعي / مسجل / حضر) و`is_expert`.
9. فلاجات `counter_visibility` لإظهار الكاونترات والتابات.
10. تصدير Excel للفرص والفعاليات وإحصائيات المنصة.
11. حقول الأثر الاقتصادي ونافذة التحضير في صفحة إعدادات لوحة التحكم.
