## 1) نظام الفرص

### 1.1 «إغاثة» → أولوية طوارئ ⭐ جديد

العميلة طلبت: **حذف تصنيف «إغاثة»**، ويتحول لـ **أولوية طوارئ**، ويفضل تحت تصنيف **«خارج الكويت»**.

يعني بقى عندنا **حاجتين منفصلين**:

| الحقل | المعنى | العرض |
|-------|--------|-------|
| `is_relief` | تصنيف **«خارج الكويت»** | أيقونة الطيارة (زي ما اتفقنا قبل كده) |
| `is_emergency` | **أولوية طوارئ** (جديد) | بادج/أيقونة طوارئ أحمر |

```json
{
  "is_relief": true,
  "is_emergency": true
}
```

**المطلوب:**

- في فورم إنشاء/تعديل الفرصة: اعمل **checkbox منفصل** لـ `is_emergency` باسم «أولوية طوارئ».
- **متشيلش** `is_relief` — هو بقى تصنيف «خارج الكويت» بس.
- في الكارت وصفحة التفاصيل: لو `is_emergency = true` اعرض بادج طوارئ واضح.

الفرص اللي `is_emergency = true` بتطلع **أول القائمة** تلقائياً من الـ API.

---

### 1.2 ترتيب الفرص — اتغير ✅ backend

العميلة قالت: **الفرص اللي بدأت تطلع بآخر الترتيب بدل الأول**.

الترتيب الجديد في `GET /api/list-volunteer-opportunities/`:

| الأولوية | الحالة |
|----------|--------|
| 0 | طوارئ / عاجلة + قادمة + فيها أماكن |
| 1 | قادمة + فيها أماكن |
| 2 | مكتملة العدد (Full) |
| 3 | **بدأت (inprogress)** ← نزلت تحت |
| 4 | منتهية / ملغية / فات موعدها |

> **ملاحظة للمراجعة مع العميلة:** حرفياً «آخر الترتيب» يعني تحت المنتهية كمان. إحنا حطينا «بدأت» **تحت كل اللي المستخدم يقدر يسجل فيه**، بس **فوق** المنتهية والملغية — لأن إظهار فرصة منتهية فوق فرصة شغالة كان هيبقى أغرب. لو العميلة عايزة حرفياً آخر حاجة خالص، قولنا وهي سطر واحد.

الفرونت **مش محتاج يعمل sort** — خد الترتيب زي ما هو جاي.

### 1.3 تصنيفات التطوع + عدد المستفيدين ⭐ جديد

تصنيف جديد للفرص التطوعية: **بيئي / خيري / تنظيمي**.

```
POST/PATCH /api/volunteer-opportunities/
```

```json
{
  "volunteer_category": "charity",
  "beneficiaries_count": 250
}
```

القيم المسموحة لـ `volunteer_category`:

| القيمة (API) | EN | AR |
|--------------|----|-----|
| `environmental` | Environmental | بيئي |
| `charity` | Charity | خيري |
| `organizational` | Organizational | تنظيمي |

**الـ response:**

```json
{
  "volunteer_category": "charity",
  "volunteer_category_display": { "en": "Charity", "ar": "خيري" },
  "beneficiaries_count": 250,
  "supports_beneficiaries_count": true
}
```

**قاعدة مهمة:** خانة **«عدد المستفيدين» تظهر وتُحسب فقط في فرص «خيري»**.

- في الفورم: اخفي حقل `beneficiaries_count` إلا لو المستخدم اختار `charity`.
- الـ backend بيتجاهل القيمة تلقائياً لأي تصنيف تاني (بترجع `null`).
- استخدم `supports_beneficiaries_count` من الـ response لو عايز تعرف تعرض الخانة أو لأ.

---

### 1.4 أيقونة «i» — خاص / عام ⭐ جديد

المطلوب: **أيقونة "i" جانب نوع الفرصة** توضح إذا كانت خاصة أو عامة.

الحقل موجود في الكارت والتفاصيل:

```json
{ "is_public": true }
```

- `is_public: true` → «فرصة عامة» — متاحة لكل المتطوعين.
- `is_public: false` → «فرصة خاصة» — بدعوة / لفريق معيّن.

اعرض tooltip على الأيقونة بالنص المناسب (بفورمات التطوع).

---

### 1.5 Backdating ✅ backend

الأدمن بقى يقدر يدخل فرصة **بتاريخ قديم بأثر رجعي**. شيلنا قيد `after_or_equal:today` من `start_date` و `due_date` في لوحة التحكم.

الفرونت: لو عندك `min` date على الـ date picker في فورم الأدمن، **شيله**.

### 1.6 «تدريب ميداني» تحت الفعاليات

نوع `learning_type = Internship` («تدريب عملي» / «تدريب ميداني») المفروض يظهر تحت قسم **«الفعاليات» (Event)** بدل «تطور».

ده **تغيير عرض بحت** — الـ API والـ routes زي ما هم (`/api/learn-serve-opportunities/`). في الـ tabs والتصنيفات، رتّب النوع ده تحت الفعاليات.

## 2) الإحصائيات والعدادات

### 2.1 عداد الأثر الاقتصادي

```
GET /api/statistics/
```

```json
{
  "grand_total_hours": 120,
  "economic_impact_rate_kwd": 6,
  "economic_impact_kwd": 720
}
```

الصيغة: **مجموع ساعات التطوع × 6 د.ك**. المعدل قابل للتغيير من الأدمن، فاقرأه من `economic_impact_rate_kwd` **متعملهوش hardcode**.

### 2.2 عدد المستفيدين ⭐ جديد

نفس الـ endpoint بقى يرجع:

```json
{
  "beneficiaries_count": 121,
  "beneficiaries_breakdown": {
    "volunteer_opportunities": 120,
    "course_learners": 1
  }
}
```

الصيغة اللي طلبتها العميلة:

```
عدد المستفيدين = مجموع المستفيدين من فرص التطوع (الخيرية فقط)
               + عدد المتعلمين من الدورات (اللي حضروا فعلاً)
```

اعرض `beneficiaries_count` كعداد. الـ `breakdown` متاح لو عايز تفصيل في tooltip.

### 2.3 إظهار العدادات حسب القيمة

**ظاهر دائماً (حتى لو صفر):**

- ساعات التطوع
- عدد فرص التطوع

**يظهر فقط لو القيمة > 0:**

- تطور (Development)
- الشهادات
- الرعاية (Sponsorship)

**مهم:** نفس القاعدة **تنطبق على التابات المرتبطة**. لو عداد الشهادات = 0، تاب «شهادات» يتخفي كمان. العميلة ذكرت ده صريح («حتى التابات»).

### 2.4 ترتيب العدادات بالموبايل ⭐ جديد

العدادات الأربعة (**Sponsor / Develop / Volunteer hrs / Certificate**) لازم تترتب **أفقياً، الأربعة جانب بعض** في الموبايل — مش تحت بعض.

ده CSS بحت. خد بالك من الـ overflow في الشاشات الصغيرة (شرط إن العدادات الظاهرة أقل من 4 يتوسطوا).

## 3) الحضور والتحضير ⭐ أهم قسم

### 3.1 التحضير اليدوي + QR مع بعض

المشكلة الحالية: **الـ QR بس** — الناشر مش بيقدر يضيف حد يدوي.

الحل: **endpoint جديد للتحضير اليدوي**، يشتغل جانب الـ QR — مش بديل له.

```
POST /api/volunteer-attendance/manual/
```

```json
{
  "opportunity_id": 12,
  "user_id": 45,
  "attendance_date": "2026-08-23",
  "total_hours": 3.5
}
```

| الحقل | مطلوب؟ | ملاحظات |
|-------|--------|---------|
| `opportunity_id` | ✅ | |
| `user_id` أو `registration_id` أو `volunteer_uuid` | ✅ (واحد منهم) | حدد المتطوع بأي طريقة |
| `attendance_date` | ❌ | افتراضي: اليوم |
| `total_hours` | ❌ | لو مبعتهاش، بتتحسب من مدة الفرصة |

**Auth:** صاحب الفرصة، أو حد عنده `scan permission`.

**الـ response:** سجل الحضور كامل.

**في الـ UI:**

- في شاشة الحضور، اعرض **الطريقتين مع بعض**: زر «Scan QR» + قائمة المسجلين مع زر «تحضير يدوي» لكل واحد.
- **متخفيش** الـ QR لما اليدوي متاح — العميلة قالت صريح «الطريقتين يشتغلوا مع بعض والناشر يختار».
- الحقول `qr_attendance_enabled` و `manual_attendance_enabled` بترجع `true` على تفاصيل الفرصة.

### 3.2 تعديل الساعات ⭐ جديد

```
PATCH /api/volunteer-attendance/{attendance_id}/hours/
```

```json
{ "total_hours": 6.5 }
```

**بيشتغل على أي سجل حضور** — يدوي أو QR. الـ backend بيعدّل الفرق بس (مش بيجمع من الأول)، فساعات المتطوع بتظل صح.

في الـ UI: خلي الساعات في جدول الحضور **قابلة للتعديل inline** (حد أقصى 24 ساعة، أقل حاجة 0).

### 3.3 Undo / تراجع عن التحضير ⭐ جديد

```
POST /api/volunteer-attendance/{attendance_id}/undo/
```

(أو `DELETE` على نفس المسار)

بيلغي التحضير **ويرجّع الساعات** للمتطوع.

**مهم:** بعد الـ undo، تقدر تحضّر نفس المتطوع **نفس اليوم** تاني بساعات مختلفة. ده الاستخدام الأساسي: غلط في التحضير → undo → تحضير صح.

في الـ UI: زر «تراجع» جانب كل سجل حضور + تأكيد قبل التنفيذ.

### 3.4 نافذة التحضير — 72 ساعة ✅ backend

- الافتراضي بقى **72 ساعة** بعد نهاية الفرصة (كان 48).
- قابل للتغيير من الأدمن (`preparation_validity_hours` في الـ config).

تفاصيل الفرصة بترجع:

```json
{
  "preparation_valid_until": "2026-08-26",
  "preparation_valid_until_at": "2026-08-26T23:59:59+00:00",
  "is_preparation_window_closed": false,
  "preparation_reopened_until": null
}
```

**في الـ UI:**

- اعرض **countdown / تاريخ إغلاق** نافذة التحضير في شاشة الحضور (استخدم `preparation_valid_until_at` للدقة بالساعة).
- لو `is_preparation_window_closed = true`: اقفل أزرار التحضير واعرض «نافذة التحضير مقفولة — كلم الأدمن».

### 3.5 تذكير قبل الإغلاق ✅ backend

في إيميل + إشعار بيروح لناشر الفرصة (ولأي حد عنده scan permission) **قبل إغلاق النافذة**، فيه عدد المتطوعين اللي لسه مش محضّرين. بيتبعت **مرة واحدة** لكل فرصة.

مفيش شغل فرونت غير إنك تعرض الإشعار في قائمة الإشعارات (شكله زي أي إشعار).

### 3.6 الأدمن يفتح النافذة يدوياً ✅ backend

```
POST /api/admin/volunteer-opportunities/{opportunity_id}/reopen-check-in/
```

```json
{ "extra_hours": 48 }
```

أو بتاريخ صريح:

```json
{ "reopen_until": "2026-09-01 23:59:00" }
```

**Auth:** أدمن بس (أي حد تاني بياخد 403).

لو عندكم شاشة أدمن في الموقع، ضيف الزر ده. غير كده الأدمن بيعملها من لوحة التحكم.

### 3.7 الورش والاستشارات — بدون تحضير ⭐ جديد

**الورش (Workshop) والاستشارات (Consultation) مش محتاجة تحضير**، لكن **ساعاتها بتتحسب** وتظهر في العدادات.

تفاصيل فرصة التطور بترجع:

```json
{
  "requires_check_in": false,
  "manual_attendance_enabled": false
}
```

**في الـ UI:**

- لو `requires_check_in = false`: **اخفي شاشة/زر التحضير بالكامل** لنوع الفرصة ده.
- الـ backend بيعتبر المسجلين «حاضرين» تلقائياً لما الفرصة تكتمل، فالعدادات بتزيد لوحدها.
- الأنواع اللي **محتاجة** تحضير: Course, Class, Internship.

## 4) الإشعارات والإيميلات

### 4.1 إيميل تحديث الفرصة — بقى فيه Diff ✅ backend

المشكلة كانت: الإيميل يقول «تم تحديث الفرصة» بدون تفاصيل.

بقى الإيميل يوضح **كل حقل اتغير، بالقيمة القديمة والجديدة**:

```
تاريخ البداية: 2026-09-08 ← 2026-09-01
عدد المشاركين: 20 ← 10
الموقع بالعربية: مدينة الكويت ← (فارغ)
```

مفيش شغل فرونت. لو بتعرضوا محتوى الإشعار في الموقع، النص بقى multi-line — **خلي بالك من `white-space: pre-line`** عشان الأسطر تبان.

### 4.2 تنبيه الطوارئ ✅ backend

اتغير المنطق زي ما طلبت العميلة:

| قبل | بعد |
|-----|-----|
| لأصدقاء فرصة بس | **كل المستخدمين النشطين** |
| 3 أيام قبل الموعد | **يومين** قبل الموعد |
| ممكن يتكرر | **مرة واحدة** لكل فرصة |

مفيش شغل فرونت.

### 4.3 زر «قراءة الكل»

الـ endpoint **موجود أصلاً** — بس مش مستخدم في الفرونت:

```
POST /api/notifications/mark-read/
```

```json
{ "mark_all": true, "is_read": true }
```

**المطلوب:** ضيف زر **«قراءة الكل» (Mark All as Read)** في قائمة الإشعارات، وبعد النجاح صفّر `unread_count`.

الـ `unread_count` راجع في `GET /api/notifications/` على مستوى الـ response (مش جوه `data`).

## 6) البروفايل ⚠️ فيه breaking change

### 6.1 الاسم مخفي (خصوصية) ⚠️

```
GET /api/public-profile/{user_id}/
```

`full_name` بقى **بيرجع `null`** للمتطوعين في البروفايل العام — خصوصية، زي ما طلبت العميلة.

```json
{
  "full_name": null,
  "display_name": "ahmed_q8",
  "nickname": "ahmed_q8",
  "profile_pic": "https://.../pic.jpg",
  "badge_info": { "name": "Gold", "image": "..." },
  "current_status": "طالب جامعي",
  "occupation": "طالب جامعي",
  "interest_display": [ ... ]
}
```

**المطلوب — اعرض بدل الاسم:**

1. الصورة (`profile_pic`)
2. الباج (`badge_info`)
3. اليوزر نيم (`display_name` أو `nickname`)
4. الوضع الحالي (`current_status`)
5. الاهتمامات (`interest_display`)

⚠️ **لو الفرونت بيعتمد على `full_name` في البروفايل العام، هيبقى فاضي.** بدّله بـ `display_name`.

> ملحوظة: ده على **البروفايل العام بس**. بروفايل المستخدم لنفسه (`/api/account/`) لسه بيرجع الاسم عادي.

### 6.2 البروفايلات كتابات

اعرض البروفايل **tabs** بدل الشكل الحالي — التفاصيل الكاملة في [الجولة الأولى، بند 2.6](./FRONTEND_OWNER_REPORT.md).

### 6.3 جودة صورة البروفايل

مؤكد تاني: **متضغطش الصورة قبل الرفع**. الـ backend بيحفظ الملف زي ما هو.

- **تاب:** فعاليات — **تاق:** منظم

### الجهات

- **تاب:** فرص (الكل / تطوع / تطور) — **تاق:** منظم / راعي
- **تاب:** فعاليات — **تاق:** منظم / راعي

`opportunity_type`: `event` | `volunteer_opportunity` | `learn_serve_opportunity`

### ⛔ تاق «خبير» — محتاج قرار

العميلة طلبت: **المتطوع يقدر ينشر ورش/دورات/استشارات، وتتحسب من ساعات تطوعه، ويظهر عليه تاق «خبير»**.

**ده مش متعمل** — دلوقتي نشر فرص التطور مسموح للجهات والفرق بس. التغيير محتاج:

1. السماح لـ `user_type = volunteer` بإنشاء `learn_serve_opportunity`
2. قاعدة إن ساعات النشر دي تتحسب في `total_volunteer_hours` (تعريفها محتاج تأكيد: ساعات الورشة نفسها؟ ولا ساعات التحضير؟)
3. شرط ظهور تاق «خبير» (أول ورشة؟ عدد معين؟)

**محتاجين قرار من العميلة على النقطتين 2 و 3 قبل التنفيذ** — عشان لو حسبناها غلط الأرقام هتبوظ ويصعب نرجعها.

## 9) التصميم والعرض

### 9.1 مقاس الكروت

- وحّد مقاس كل الكروت على **مربع (زي انستغرام)**.
- خد بالك: **متبوظش نسبة الصورة** في صفحة التفاصيل لما الأدمن يغيّر صورة الفعالية من لوحة التحكم.
- نفس الكلام على **العنوان** — متقصّهوش بشكل يبوظ الشكل.

### 9.2 حالات الأزرار الستة

| الزر | الشرط | من الـ API |
|------|-------|-----------|
| **Register** | الفرصة مفتوحة للتسجيل | `is_registration_open = true` و `is_registered = false` |
| **Unregister** | المستخدم مسجل | `is_registered = true` |
| **Full** | العدد اكتمل | `registered_volunteers_count >= participants_needed` |
| **Closed** | فات الموعد أو أُغلق يدوياً | `is_registration_closed = true` أو `is_registration_open = false` |
| **Started** | بدأت ولسه مخلصتش | `opportunity_status = inprogress` |
| **Ended** | خلصت | `opportunity_status = completed` |

الترتيب المنطقي للفحص: `Ended` → `Started` → `Full` → `Closed` → `Unregister` → `Register`.

النصوص العربية: بدأت / انتهت / مكتمل / مغلق.

### 9.3 الترجمة

العميلة قالت **«الترجمة لا تعمل بشكل جيد»** — ده عام جداً. الـ API بيرجع `_en` و `_ar` لكل الحقول النصية وبيحترم هيدر `Lang`.

**محتاجين منكم:** لستة بالشاشات اللي الترجمة باظت فيها بالظبط (screenshot + الـ endpoint) وأنا أراجع لو المشكلة من الـ API. لو المشكلة في مفاتيح i18n في الفرونت، دي عندكم.

**تشيك سريع:** ابعت هيدر `Lang: ar` أو `Lang: en` مع كل request وشوف لو `msg` رجعت باللغة الصح.

## 10) التقارير ⛔ Blocked

العميلة طلبت:

1. تقرير شامل لكل الأطراف يشمل **«شهادة تطوع» قابلة للإصدار**
2. تقرير خاص بالجهات (Organizations Report)
3. **الرقم المدني والترخيص يطلعوا في التقرير**

الملف بيقول «تم إرسال طريقة التقرير» — **إحنا مستلمينهاش**.

النقطة 3 جاهزة: `civil_id` و `registration_number` موجودين في الـ API.

النقطتين 1 و 2 محتاجين **الـ template / الـ layout** المطلوب (أعمدة؟ PDF ولا Excel؟ شكل الشهادة؟). ابعتوا الملف وأنا أعمل الـ endpoints.

### 11.1 أنواع الجهات — الليستة الجديدة ⚠️ breaking

```
GET /api/choices/org_type/
```

بقى يرجع **6 خيارات بس**:

| value_en | value_ar |
|----------|----------|
| `Institution` | وزارة / هيئة حكومية |
| `Education` | جامعة / مدرسة / معهد |
| `Society` | جمعية تعاونية / مجتمع |
| `NGO` | جمعية خيرية / غير ربحية |
| `Volunteer Team` | فريق تطوعي |
| `Commercial` | شركة تجارية / براند |

⚠️ **الخيارات القديمة اتشالت:** `Private`, `Public`, `Community`, `Company`, `Government`.

**لو الفرونت فيه أي نوع جهة hardcoded، هيتكسر.** اقرأ الليستة من الـ endpoint دايماً.

الجهات الموجودة اتنقلت تلقائياً:

| كان | بقى |
|-----|-----|
| Government / Public | Institution |
| Private / Company | Commercial |
| Community | **Society** |

> ملاحظة: `Community` بقى اسمه `Society`. لو كنتم بتتشيكوا على `"Community"` بالاسم (مثلاً لإخفاء حقل الترخيص)، غيّروه لـ `"Society"`. الـ endpoint `GET /api/check-license-requirement/` بيتعامل مع الاتنين، فاعتمد عليه بدل الأسماء.

### 11.2 القطاع (Sector)

العميلة طلبت **حذف القطاع**.

**مشيلناهوش من الـ API** بشكل مقصود: `sector` و `sector_display` مستخدمين في 8 resources وشيلهم دلوقتي هيكسر الفرونت فوراً.

**الخطة:**

1. **إنتوا:** شيلوا حقل القطاع من **فورم التسجيل** وشاشات عرض البروفايل. مش مطلوب ومش مبعوت.
2. **إحنا:** بعد ما تأكدوا إن مفيش حاجة بتقراه، نشيل الحقول من الـ API في PR منفصل.

قولولي لما تخلصوا الخطوة 1.
